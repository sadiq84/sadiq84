Subscription Boundaries

Separate subscriptions by environment (Dev, UAT, Prod) and function (Platform vs Application) to prevent noisy neighbor bottlenecks and drastically minimize blast radius.

1. IP Address Management (IPAM) & CIDRs

Comprehensive on-premise CIDR assessment to guarantee non-overlapping RFC 1918 address space. Dedicated supernets allocated for Hub (10.100.0.0/16), Workload Spoke 1 (10.101.0.0/16), and Shared Tools Spoke 2 (10.102.0.0/16).

2. Centralized Traffic Inspection (UDRs)

User-Defined Routes (UDRs) associated with spoke subnets override default Azure routing: 0.0.0.0/0 → Azure Firewall Private IP (10.100.1.4). Spoke-to-spoke and egress traffic undergoes Deep Packet Inspection (DPI) and TLS termination.

3. Ingress & Egress Edge Security

Centralized egress filtering prevents data exfiltration. Ingress public web traffic terminates at Azure Application Gateway or Azure Front Door with Web Application Firewall (WAF) enabled in OWASP CRS 3.2 prevention mode before reaching private spokes.

4. Private Connectivity (Private Link)

Zero public IP addresses on enterprise databases or storage. PaaS services (Key Vault, Azure SQL, Blob Storage) connect solely via Private Endpoints with centralized Private DNS Zones linked across all VNets.

Remote State Management

Stored in private, firewall-restricted Azure Blob Storage with automated blob lease locking to prevent race conditions. Access exclusively through Azure Managed Identity; local state or shared credentials strictly prohibited.

Modularity & Semantic Versioning

Parameterized, independent Terraform modules (Networking, Compute, Storage, Monitoring). Workspaces or root modules pin exact Git tags (e.g., source = "git::...?ref=v2.4.1") to guarantee deterministic builds.

Automated Nightly Drift Detection

Nightly cron pipeline executes terraform plan -detailed-exitcode. Exit code 2 triggers an immediate Teams / Slack alert, isolating unauthorized console changes before they cause production outages.

Azure Repos & DevSecOps Pipelines

Trunk-Based Governance & Multi-Stage YAML Workflows

CI/CD Standards
Trunk-Based Branching Model

Developers create short-lived branches (feature/*, fix/*) merging directly into main via Pull Request. Eliminates long-lived branch divergence and complex merge debt.

Strict Branch Protection on main
Min 2 Senior Reviewers + CODEOWNERS
"No Direct Push" & "No Branch Deletion"
YAML Template Flow Stages
1. Validate & Test terraform fmt/validate
2. Security & Secrets GitLeaks + Checkov + Trivy
3. Build & Plan Artifact published
4. Production Gate Manual approval required
5. Automated Rollback On failure trigger
azure-pipelines-devsecops.yml 
trigger:
  branches:
    include: [ main ]

stages:
  - stage: SecurityScan
    displayName: 'Shift-Left Security & Lint'
    jobs:
      - job: StaticAnalysis
        pool: { vmImage: 'ubuntu-latest' }
        steps:
          - script: gitleaks detect --source . --verbose
            displayName: 'Secrets Detection (GitLeaks)'
          - script: checkov -d . --framework terraform --output junitxml --output-file-path $(Common.TestResultsDirectory)/checkov.xml
            displayName: 'IaC Security Baseline (Checkov)'
          - script: infracost breakdown --path . --format json --out-file /tmp/infracost.json
            displayName: 'FinOps Cost Shift-Left (Infracost)'

  - stage: PlanAndApproval
    displayName: 'Terraform Plan & Gate'
    jobs:
      - deployment: PlanGate
        environment: 'Azure-Production-Env'
        strategy:
          runOnce:
            deploy:
              steps:
                - script: terraform plan -out=tfplan -input=false
                  displayName: 'Generate Executable Plan Artifact'

  - stage: ApplyDeployment
    displayName: 'Controlled Apply & Rollback'
    dependsOn: PlanAndApproval
    jobs:
      - job: Apply
        steps:
          - script: terraform apply tfplan
            displayName: 'Execute Infrastructure State Transition'

FinOps (Cloud Financial Management)

28% Realized Cloud Spend Optimization Framework

-28% Cloud ROI

FinOps is not just cutting costs—it is maximizing business value per dollar spent through financial accountability, real-time visibility, and proactive automation.

1. Waste Elimination

Automated sweeps for unattached Managed Disks, orphaned snapshots, idle compute instances, and unused static public IPs saving up to 10-15% instantly.

2. Rightsizing Strategy

Analyze 30-day CPU/memory utilization percentiles (P95). Downsize over-provisioned VMs and reallocate underutilized database tiers with zero performance impact.

3. Commitment Discounts

Lock in 1-year or 3-year Reserved Instances (RI) and Azure Savings Plans for steady-state workloads, achieving up to 45% - 72% savings compared to Pay-As-You-Go.

4. Automated Scheduling

Automated start/stop schedules via Azure Automation runbooks for non-production (Dev, Test, UAT) environments outside business hours, saving 65% on test environments.

5. Log Ingestion Tuning

Filter noisy telemetry at source via Azure Monitor Agent (AMA) Data Collection Rules (DCR). Exclude high-volume verbose logs to cut Log Analytics ingestion invoices by over 40%.

6. Mandatory Cost Allocation Tagging

Enforce tags at subscription boundaries via Azure Policy: Environment, CostCenter, Owner, and ApplicationId for 100% cost attribution.

Backup, Disaster Recovery & High Availability

RTO / RPO Guarantees & Multi-Region Failover Architecture

Business Continuity
RTO (Recovery Time Objective) ≤ 30 Minutes

The maximum acceptable elapsed wall-clock duration of system downtime before core applications and business services are completely restored.

RPO (Recovery Point Objective) ≤ 15 Minutes

The maximum acceptable quantum of data loss measured backward in time from an unplanned outage (e.g. maximum 15 minutes of transactional delta).

Redundancy Model Physical Distribution Durability SLA Target Architectural Tier
LRS (Locally Redundant) 3 synchronous copies within a single physical datacenter 99.999999999% (11 9's) Dev/Test workloads, non-critical logs
ZRS (Zone-Redundant) 3 synchronous copies across 3 distinct Availability Zones 99.9999999999% (12 9's) High-Availability Production Workloads
GRS / GZRS (Geo-Redundant) Zone-redundant in primary + replicated to secondary paired region 99.99999999999999% (16 9's) Tier-0 Mission Critical & Disaster Recovery
Multi-Region DR Strategy: Primary active region (e.g., East US) runs Virtual Machine Scale Sets (VMSS) across 3 Availability Zones. Azure Site Recovery (ASR) continuously replicates compute disks asynchronously to the paired secondary region (e.g., West US), ready for automated failover orchestration.
